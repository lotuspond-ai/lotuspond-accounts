### What the end-to-end tests show, against the real Hydra

- A new person signs up from a product's sign-in, confirms the email from the outbox, and the product gets a code. Exchanging it with the PKCE verifier gives an ID token with `iss`, `aud`, `sub`, `email`, `email_verified: true`, `region: "in"`, `nonce`, `amr: ["pwd"]` and `sid`, and no `name` without the `profile` scope.
- The same browser signs in again with `prompt=none`, with no page. A browser with no session gets `login_required`.
- **PKCE:** `code_challenge_method=plain` and a missing `code_challenge` both end in an error and no code. Hydra's own log gives the reasons: "plain is not allowed" and "must include a code_challenge". A wrong verifier gets `invalid_grant`. This closes the item M1 left open.
- An application that is not a registered LotusPond product gets `access_denied` at consent.
- A product's sign-out (with `id_token_hint`) shows the confirmation page, then returns to the product's post-logout address; `prompt=none` afterwards needs a sign-in.
- A password reset ends the Hydra session in another browser: `prompt=none` there then needs a sign-in.

## Found while testing

- **Hydra v26 challenges can end in `=`.** The first version of the challenge check refused them, so about half of all sign-ins showed "This sign-in has expired". Fixed, with a test.
- **Hydra refuses `post_logout_redirect_uri` without `id_token_hint`** ("Logout failed because query parameter post_logout_redirect_uri is set but id_token_hint is missing"), and likewise `state`. A product that wants to be sent back after sign-out has to keep the ID token and send it as the hint. Recorded as a test.

## Checked for Health's sign-in, 17 November 2026 (later)

Against the real Hydra v26.2.0, local stack:

- **`prompt=create` is refused.** Hydra shows the sign-in page, then aborts with "Used unknown value '[create]' for prompt parameter", and the product gets no code. Products send `screen_hint=signup` instead; Accounts opens the sign-up page for it. End-to-end test added (9 tests, two runs, all pass).
- **An expired ID token works as `id_token_hint`.** Hydra ran with a 10-second ID token lifetime for this check only. 15 seconds after issue, logout with the expired token as the hint, `post_logout_redirect_uri` and `state` showed the confirmation page. After confirming, Hydra returned to `http://localhost:9999/signed-out?state=bye`. So a product can keep a session's ID token for the whole session and use it to sign out.
