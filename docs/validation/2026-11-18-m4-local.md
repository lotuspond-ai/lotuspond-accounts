**Nothing has been created on AWS.** AWS refused the credentials in this development environment (`InvalidClientTokenId` from `sts get-caller-identity`), so no stack, server, SES identity or DNS record exists for staging. Everything below ran locally. `docs/staging.md` is the runbook to apply it.

## Found while testing

- **`docker cp` makes the import unreadable.** It writes the file as root with owner-only permissions, and the app container runs as the unprivileged `node` user, so `accounts-cli import` failed with `EACCES`. Files now go in and out through `docker compose exec`, and the runbook says the same.
- **An empty `SES_CONFIGURATION_SET`** from the compose file would have failed configuration in production. It now means none, with a test.
