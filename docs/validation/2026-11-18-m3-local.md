# M3 validation: Health against the real Accounts, local, 18 November 2026

**Where:** the development container, with the Accounts stack (`deploy/docker-compose.yml`, `docker-compose.local.yml` and `docker-compose.health.yml`: plain HTTP, Hydra v26.2.0 in `--dev`, the mail outbox). LotusPond Health ran on the same machine from `lotuspond-ai/lotuspond-health` branch `claude/sleepy-hamilton-zqrfgd` (PR #48, commit `92bcf27`, stacked on PR #40), with a throwaway database. It was registered at Accounts as a confidential client, with back-channel logout to this machine.

**Not checked here:** any server, real TLS, Hydra without `--dev`, Amazon SES, regional hosts (one Health host served every region), universal links or a phone, or a company-managed (`org`) account, which Accounts cannot create in step 1.

## Results

`tools/health-e2e.sh` runs `test-e2e/health.test.ts`, 7 tests, through Health's own endpoints, as its website and apps call them:

| Test | Result |
| --- | --- |
| Health's "Create account" opens Accounts' sign-up (`screen_hint=signup`). After the email is confirmed, Health finishes its own sign-up (`/api/auth/accounts/complete`) and the session is for that email. | Pass |
| Signing out of Health goes to Accounts with the session's ID token as `id_token_hint` and `post_logout_redirect_uri` set to Health's `/login`. Accounts asks "LotusPond Health asked to sign you out", then returns to Health's `/login`. A later sign-in asks for the password again. | Pass |
| A returning person signs in to Health with their Accounts password, into the same Health account. After signing out of Health only, Health's silent check (`prompt=none`) signs them back in with no page. | Pass |
| A silent check from a browser not signed in at Accounts lands on Health's `/login`. | Pass |
| **A password reset at Accounts ends the Health session through back-channel logout.** Hydra's log shows "Back-Channel Logout Request" posts to Health's `/api/auth/accounts/backchannel-logout`, and Health refused none. | Pass |
| An existing Health password account is joined on its first Accounts sign-in, once the email is confirmed, into the same Health account id. | Pass |
| The app signs in through the system browser: Health hands back a one-time code, the app trades it with its PKCE verifier for a pending sign-up, finishes it, and its bearer token reads the account. | Pass |

Run twice, both passing. Accounts' own suites passed in the same stack: `npm run check` (54) and `tools/e2e.sh` (9).

### Control: Health without the fixes in PR #48

The same 7 tests against PR #40 alone (commit `752d54d`): **5 fail, 2 pass**. Every failure is at Health's "Create account": PR #40 sends `prompt=create`, which Hydra refuses, so the sign-up never reaches Accounts' page. The two that pass never use that path: the silent check, and joining an existing account from the sign-in page.

The sign-out test fails at its sign-up step, before it reaches sign-out, so the control does not show the hint problem by itself. Accounts' own end-to-end test does: Hydra refuses a return address without `id_token_hint`.

## Found while testing

- **The first version of `tools/health-e2e.sh` left Health running.** Stopping it killed only `npx`, not the server under it. The next run's server could not bind the port, and its requests reached the old server, whose database the script had deleted, which gave 500s. The first control run was invalid for this reason. The script now starts Health in its own process group and stops all of it, refuses to start if the port is taken, and checks that the server answering is the one it started.
